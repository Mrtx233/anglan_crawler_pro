# 商品采集与数据处理工作台

统一管理四阶段流程：分类页链接采集 → 商品 JSON 采集 → 字段规范与合并 → Shopify/WooCommerce 转换导出。目录名保留不变。

## 启动

需要带 Tkinter 的 Python、Chromium 系浏览器，以及 requirements.txt 中的依赖。

```sh
cd "/Users/malyu/Downloads/PythonCode/Anglan_Crawler_Pro_Max/Complete three-stage process Json"
python3 -m pip install -r requirements.txt
python3 main.py
```

顶部可填写浏览器代理。代理默认为 `http://127.0.0.1:7897`，留空时不给浏览器显式设置代理。商品采集的汇率请求使用 Python 的网络代理环境，不直接使用此输入框。HTTPS 请求在默认信任配置基础上加载 `certifi` CA 证书，并保留证书和主机名校验，以兼容 macOS Python 缺失默认 CA 文件的环境。

## 操作

### ① 链接采集

第一阶段固定使用项目根目录的 `01INPUT_XLSX/`，无需选择保存根目录：

1. 从下拉框选择已有批次，或手动输入新批次，例如 `A0916`。
2. 选择该批次下已有负责人，或手动输入新负责人，例如 `陈港`。
3. 填写任务文件夹名称，例如 `补delfias.com礼服`，点击「创建文件夹」。

创建时一并建立不存在的批次和负责人目录。程序清理新名称中的空格、隐藏字符和非法路径字符，界面显示清理后的相对路径。已有同名目录直接沿用，不删除内容；修改选择后重新创建或直接开始采集。开始采集也会自动准备任务目录。「刷新」重新读取批次和负责人目录。

示例产物：`01INPUT_XLSX/A0916/陈港/补delfias.com礼服/babaroni.co.uk.json`。第二阶段输出到同级的 `02OUTPUT_XLSX/A0916/陈港/补delfias.com礼服/`。

链接表按域名一个 JSON 文件，内容是「分类名 → 商品链接数组」：

```json
{
  "Prom Dresses": [
    "https://babaroni.co.uk/products/example-dress-a",
    "https://babaroni.co.uk/products/example-dress-b"
  ],
  "Bridesmaid Dresses": [
    "https://babaroni.co.uk/products/example-dress-c"
  ]
}
```

同一域名再次采集会读入原文件并在对应分类下追加去重，旧链接不会丢失；分类按首次出现顺序保留。同目录另有 `links_index.json`，记录「域名 → 分类 → 分类页 URL」，只作追溯用，读取链接表时会自动跳过。原文件无法解析时本轮结果另存为 `{域名}.recovery-<时间戳>.json`，绝不覆盖原文件。

输入每行一个分类，例如：

```text
Prom Dresses, https://babaroni.co.uk/collections/prom-dresses
```

也可以粘贴 `PAGES = [("分类名称", "https://example.com/collections/dresses"), ...]`，点击「解析为表格」显示“分类名称 / 分类 URL”两列。点击「返回文本编辑」可修改原始输入并重新解析；表格模式下采集使用当前解析结果。列表按字面量安全解析，不执行粘贴的代码。

还支持直接粘贴「域名 → 分类名 → 分类页 URL 数组」JSON（与 `links_index.json` 结构一致）：

```json
{
  "opulentempire.ca": {
    "Men Shirts": ["https://opulentempire.ca/collections/men-shirts"],
    "Men Sweaters Cardigans": ["https://opulentempire.ca/collections/men-sweaters-cardigans"],
    "Men Suits": ["https://opulentempire.ca/collections/men-suits"]
  }
}
```

支持多个域名、同一分类多个 URL，按 JSON 中的顺序展开为分类任务；空数组跳过。外层域名用作分组，实际访问地址及后续保存域名仍以 URL 为准。既可先点击「解析为表格」预览，也可直接开始采集。JSON 语法、分类结构或 URL 错误会明确报错，不会退回逐行解析。

可填每分类页数和 XPath；页数留空不限。点击「开始链接采集」，按域名保存 分类名/链接 JSON。

完成后点击「交给下一阶段」，自动填写商品采集的输入目录并读取文件列表，不自动开始采集。

### ② 商品采集

可接受第一阶段交接，也可直接选择已有链接表目录并点击「读取文件夹」。文件行及分类行支持图片保留、跳过规则；选中后点击「编辑图片规则」或双击行编辑。文件块可全部展开或折叠。

保留 `1,2` 表示仅保留对应位置，跳过 `-1` 表示跳过最后一张；分类两栏均空时继承文件规则，任一栏非空时该分类独立配置。分类栏 `-` 表示显式不过滤。两栏同时设置时保留优先。

开始采集后，输出 `{域名}商品.json` 到 `01INPUT_XLSX` 对应的 `02OUTPUT_XLSX` 目录；无该路径段时使用输入目录下的 `02OUTPUT_XLSX` 子目录。文件名为 `{域名}商品.json`，与第一阶段的 `{域名}.json` 不会同名。续采基于已有输出中的 `link_href`。

商品记录按「域名 + 商品数组」保存，每条记录如下：

```json
{
  "domain": "bearbottomclothing.com",
  "products": [
    {
      "category": "Prom Dresses",
      "name": "Midweight Supima Tee",
      "link_href": "https://bearbottomclothing.com/products/midweight-supima-tee",
      "details": "<p>An everyday staple...</p>",
      "options": [
        {"name": "Color", "values": ["Navy", "Bone"]},
        {"name": "Size", "values": ["S", "M", "L"]}
      ],
      "default_price": ["40", "40"],
      "variant_images": {
        "Navy": "https://.../Navy_600x600.jpg",
        "Bone": "https://.../Bone_600x600.jpg"
      },
      "variant_overrides": [
        {"options": {"Color": "Bone", "Size": "S"}, "price": ["42", "55"]}
      ],
      "src_links": ["https://.../a_600x600.jpg", "https://.../b_600x600.jpg"]
    }
  ]
}
```

字段语义：

- `category` 沿用第一阶段的分类名，不做层级拆分。
- `options` 的**选项名已规范化**：尺码类统一为 `Size`，原 `Type` 改为 `Style`（Shopify 保留属性名），`color` 被提到首位；原始选项名不可从记录还原。
- 选项值里含 `custom` 的（如 `Custom Size`、`Custom Made`）会在产出时**直接剔除**——定制项不是可履约的真实变体，导出到 Shopify 会变成卖不了的 SKU。关键字在 `config.EXCLUDED_VALUE_KEYWORDS` 配置，子串匹配、不分大小写。`options`、`variant_overrides`、`variant_images` 三处同步剔除，不会残留；某个选项的值被剔空时该选项整个丢弃。
- `variant_images` 的键即 `options[0]` 的取值（有颜色时就是颜色值）。
- `default_price` 是 `[售价, 划线价]`；划线价缺失时退回售价。
- `variant_overrides` 只收录价格与 `default_price` **不同**的选项组合，每条含该组合的选项值与价格对。因此**「缺失」应理解为「该组合取 `default_price`」**，该数组为空即代表全部变体同价。
- `src_links` 为缩略图 URL 数组。
- 价格为**按元直接解析**（`"40"` 即 40 元），不再有「不含小数点按分处理」的规则。

完成后点击「交给下一阶段」，自动填写中间表目录，不自动执行转换。恢复文件（`{域名}商品.recovery-<时间戳>.json`）需要人工检查，不自动并入正常结果。旧 XLSX 中间表读取失败时同样另存恢复文件，绝不覆盖原文件。

### ③ 规范与合并

选择中间表所在目录，页面显示识别的目标域名和品牌。目录末级名称应包含目标域名，例如 `补delfias.com礼服`；来源文件使用原域名命名。

选定目录后会自动扫描其中的 `{域名}商品.json`，在下方的商品记录卡片里逐个文件汇总：文件、商品数、以及该文件**出现过的选项名**。同名选项跨商品合并去重，只列名字不统计取值——这里关心的是「这批数据有哪些维度可供展开」。单个文件解析失败只记入日志，不影响其余文件。

汇总表下方的「参与转换的选项」列出整个目录出现过的选项名（跨文件取并集），每个选项一个勾选框。**勾上=该选项参与转换，取消=该选项维度整个不写进中间表**。勾选状态在重新读取目录后按选项名保留，运行期间禁用。

点击「开始规范与合并」后按顺序执行：

1. **按勾选把每个 `{域名}商品.json` 转成同目录的 `{域名}商品.xlsx`**（见下）
2. **逐个读取生成的 xlsx 做字段规范**（下表）
3. **合并为一个 `processing_results/<目录名>_合并.xlsx`**

### 第 1 步：JSON → 十列中间表

每个 JSON 各生成一个同目录的 `{域名}商品.xlsx`，再逐个进入字段校验。

转换**以界面上的勾选为准**：**未勾选的选项维度完全不写进 `styles1`**——选项名、取值、变体段都不写。因此该维度在中间表里根本不存在，第四阶段不会展开它，**产出行数随之真正减少**：

```text
options: Color=[R,B], Size=[S,M]，两者都勾
  styles1 = Color#R&Size&S$19.99$24.99@red.jpg#R&Size&M...#B&Size&S...#B&Size&M...
  -> 4 段

取消勾选 Size（只留 Color）
  styles1 = Color#R$19.99$24.99@red.jpg#B$21.99$25.99@blue.jpg
  -> 2 段，Size 彻底消失
```

注意：`variant_images` 的键是 `options[0]`（通常是颜色）的取值。**只有第一个已勾选的维度叫 Color 时，变体段才会追加 `@` 图片**；判定用维度名而不是位置，因为采集端把 color 排到了 options 首位，这张映射实质是「颜色值 → 该颜色的图」。取消勾选 Color 后第 1 维换成 Size 之类的维度，再去查这张映射就是把尺寸值当颜色值碰运气——查不到倒还好，一旦某个尺寸值恰好等于某个颜色值，就会给该变体挂上一张张冠李戴的图。因此只勾 `Size` 时该商品的变体段都不带 `@`。

转换**每次运行都无条件重做**，不比对时间戳。因为生成的 `{域名}商品.xlsx` 能通过全部输入过滤条件（`_合并`、`~`、`.`、`.recovery-` 都拦不住它），一旦被重新采集的 JSON 甩在后面就会被当成有效输入消费、把过期数据混进合并表；重转是消除这个竞态的可靠办法。整批里任何一条商品编码失败都会中止且**不留下半成品 xlsx**。源中间表保持原样，JSON 不会被改动。

记录到中间表的字段映射：

| 中间表列 | 来源 |
|---|---|
| title | 记录的 `category` |
| name | 记录的 `name` |
| price1 / price2 | `default_price` 的 `[0]` / `[1]` |
| styles1 | 由**已勾选的** `options` 维度展开的内嵌变体段（见下） |
| styles2 / styles3 | 留空——所有维度都内嵌在 styles1 |
| src_links | 记录的 `src_links`，用 `#` 拼接 |
| link-href | 记录的 `link_href` |
| details | 记录的 `details` |

styles1 的格式是 `组头#段#段...`，组头为**第一个已勾选**的选项名，每段为 `值1&名称2&值2&名称3&值3$售价$划线价@图片URL`（无图片时不追加 `@`）：

```text
Color#Red&Size&S$19.99$24.99@https://cdn.example/red_600x600.jpg#Blue&Size&M$21.99$25.99
```

编码规则：

- 分隔符 `\ & # @` 转义（先转义反斜杠），因此选项值里带这些字符不会破坏分段。
- 价格取 `variant_overrides` 里匹配**保留维度**组合的条目，没有则用 `default_price`。
- 图片按保留后的第 1 维取值查 `variant_images`，**且仅当该维度的名字是 Color 时**才追加 `@`。详见上一节。
- 只编码**前三维**；第四维及以后无法表示（转换阶段只读 option1/2/3），会被截断并在日志里说明。
- 选项名/值里含 `$` 会**报错中止**：`$` 既不在转义集内，解码端又是按最右侧两个 `$` 切分价格，无法安全表示。未勾选的维度不参与编码，因此它含 `$` 也不会报错。若真实数据里出现，需要先在采集端处理。
- 一个都不勾（或勾的名字在本商品上都不存在）时退化为单个无组头的段，保证每个商品至少产出一行。

已知信息损失：`variant_overrides` 只收录价格**异于** `default_price` 的组合，「不在 overrides 里」既可能是「等于默认价」也可能是「该组合没有变体」，JSON 未保留区分二者所需的信息，因此统一取 `default_price`。剔除维度后原本价格不同的两个组合可能落到同一个键上，此时保留先出现的那条。

### 第 2、3 步：字段规范与合并

生成的 xlsx 作为普通中间表进入字段规范，源中间表保持原样。此阶段不执行转换；完成后点击「继续到转换与导出」，将本次合并表交给第四步，不自动运行。

| 字段 | 当前规则 |
|---|---|
| title | 清理禁止符号、Title Case、标准层级空格、最多两级和 100 字符 |
| name | 根据文件/文件夹域名替换旧品牌，清理符号，规范大小写；含非英文文字或未支持字符时跳过整件商品并记录文件、行号和原名称 |
| price1 | 非负数字、十进制四舍五入到两位小数 |
| price2 | 两位小数，低于 price1 时设为其 1.1 倍 |
| src_links | 独有前四张，再接上与 styles1 共有的图片 |
| 其他字段 | 保持读取值，不增加清洗规则 |

title/name 保留数字分数中的斜杠。字段失败会报告真实 Excel 行号，整批不写合并表或启动转换。处理平台只读取 `*商品.xlsx`，自动跳过第一阶段的链接 JSON、临时文件、历史合并表、导出表和 recovery，重复运行不会重新合并子目录结果。

### ④ 转换与导出

接受第三步交接的合并表，或点击「选择文件」选择已有 XLSX 合并表，然后点击「开始转换与导出」。无需重新读取中间表目录、识别品牌或再次清洗字段。**页面上没有维度相关的开关**——维度该在第三阶段按勾选裁掉，这里只做转换。

沿用原转换规则，在所选合并表所在目录生成 `xlsx/`、`csv/` 和 WooCommerce 输出。包含 Shopify 原价与价格匹配文件、两套 WooCommerce CSV，以及价格库尚未使用的价格清单。转换不会改写合并表。

价格匹配版中，同一商品（Handle）的所有有效价格变体共用一个划线价：取匹配后的最高售价，直接向上取整，不再乘以 1.2。例如售价为 `30.54 / 30.95 / 30.99`，划线价统一为 `31`。未匹配成功的变体保留原售价，该售价也参与最高值计算；整件商品均未匹配时也按此规则更新划线价。纯图片行不参与计算，也不填入划线价。原价版保持原有价格。

维度裁剪**只在第三阶段做**：未勾选的选项不会写进合并表的 `styles1`，所以到这里行数已经定下来了。第四阶段仍会收到同一份勾选并再按选项名过滤一次（名字来源见下），因为中间表可能来自更早的运行、或用户手工放入，保留这层过滤可保证行为一致。按名字而非位置匹配，因为同一位置在不同商品上可能是不同选项。

名字的来源随编码方式而变——第三阶段新生成的中间表取每个变体段内嵌的 `&名称&值`，传统分列的中间表取 `styles2/styles3` 的组头名，段内名优先、组头回落。**因此同一个位置在 A 商品上叫 Size、在 B 商品上叫 Style 时，勾选会各自正确匹配。**

两个限制需知情：

- **第 1 维永远展开**，不受勾选影响。每个变体段自带该变体的价格与图片，丢掉第 1 维会让所有行退化成同一个变体的价格。因此「只勾 Size」时若第 1 维本来就是 Color，仍会输出 Color。
- 勾选**为空的组合**（或全部选项名都匹配不上）会退回只展开第 1 维，此时会在日志里说明；保证每个商品至少产出一行变体。

> **内嵌编码下丢维度不减行数。** 第三阶段生成的中间表把每个变体组合编成一个段，因此 `styles1` 的段数就是变体数。若中间表是**已经生成好的**（例如手工放入、或上次运行时勾了别的选项），第四阶段再丢维度只会把对应的 `Option N Name/Value` 留空，不会减少行数。**要真正减少行数，请在第三阶段取消勾选对应选项后重新运行规范与合并**——那一步会在编码时就把该维度去掉。传统分列的中间表不受此限。

被丢弃的维度在 Shopify 输出里对应的 `Option N Name` / `Option N Value` 留空。

## 任务、日志与停止

- 左侧可随时切换页面，同一时间仅运行一个任务。运行时路径、图片规则和代理输入控件禁用。
- 不提供任务名称、任务保存或打开功能，不自动保存和恢复设置，也不创建 `local_state/`。每次启动使用默认设置；采集续跑依据已有的链接 JSON 与商品中间表。
- 点击左侧「运行日志」打开独立弹窗，可按阶段筛选或仅查看错误/警告；主窗口保持当前阶段，采集继续运行。关闭日志弹窗仅隐藏，再次打开保留日志和筛选条件；退出整个程序后清空，不写入磁盘。任务失败或部分失败时自动显示日志弹窗。
- 阶段状态包含待运行、运行中、完成、无数据、部分失败、已停止和失败；保存失败按失败处理，恢复另存及部分商品失败会提示部分失败。
- 「停止并收尾」请求采集停止并保存；商品浏览器当前请求可能需要等待。第三阶段在读表和行规范时检查停止，第四阶段在转换和导出步骤间检查停止，正在写入的步骤先完成。
- 运行中关闭主窗口会请求停止并等待线程收尾，不使用强制超时退出。收尾失败时保留主窗口并显示日志弹窗；浏览器请求阻塞时也需等待返回。
- 第四阶段中途停止或导出失败可能已有部分输出，请核对日志后重新运行。

```text
  product_parser.py             旧 styles1 中间表解析（保留供回退）
  scraper_runner.py             采集主循环
stages/data_processing/         第三、四阶段业务代码
  file_utils.py                 商品记录 JSON 汇总扫描与 XLSX 中间表读写
  record_import.py              商品记录 JSON → 十列中间表（styles1 内嵌编码、按勾选裁维度）
  processing_runner.py          字段规范与合并
  converter.py                  Shopify/WP 转换与价格匹配
  conversion_runner.py          独立转换入口
  style_utils.py                感知转义的 styles 文本切分
  field_rules/                  每个字段独立的规范文件
```

业务模块从现有三个项目移入独立包，使用明确的包导入，不再争用顶层 config/logger/file_utils。该目录可以独立启动；旧项目保留独立入口。此版本业务代码是独立副本，后续规则更新需明确维护目标，不会自动同步旧项目。

**分层约束**：`stages/data_processing` 不得导入 `stages/product_collection`。两个包各带一份逐字相同的 `_STYLE_RESERVED = r"\&#@"`（转义集），第四阶段因此能独立编解码 styles 文本而不反向依赖。`record_import.py` 的编码器与 `style_utils` 的解码器共用同一份定义。

维度裁剪的三处协作，改任一环节都要一起看：

| 环节 | 位置 | 作用 |
|---|---|---|
| 界面勾选 | `app/window.py` `selected_options()` | 未扫描过时返回 `None`（不限制），否则返回勾选名列表 |
| 编码时裁剪 | `record_import._option_dimensions` | **行数真正减少的地方**：未勾选维度不写进 styles1 |
| 转换时过滤 | `converter._styles_to_shopify` 的 `expand_options` | 兜底：中间表可能来自更早的运行或手工放入 |

整合保留现有业务规则：包括变体笛卡尔积、styles1 编码与价格匹配（第三、四阶段仍在使用）。styles1 内部价格尚未规范，Shopify 转换仍可能优先使用该变体价格，而不是合并表 price1/price2。导出的 Handle/SKU 仍按原逻辑随机生成。

第二阶段的价格解析已改为**按元直接解析**：旧版把不含小数点的价格按「分」处理（`"40"` → `0.4`），新版一律按元读取（`"40"` → `40`）。经真实采集数据核对，styles1 中出现的全部价格串都带小数点，该启发式在实际数据上从未生效，因此这一改动不影响已有结果。

统一版本额外补充保存失败状态传递、分类异常记录和第三阶段的协作式停止检查，不把 GUI 整合视为数据规则重新设计。

程序不创建本地状态目录；Python 缓存由本目录 .gitignore 排除；仓库根目录输入、输出数据的忽略规则继续生效。

## 验证与范围

当前代码已检查 Python 语法、GUI 启动与五个页面切换。汇率接口已单独在线验证，成功返回 166 种币种汇率。第二阶段 JSON 输出已用脚本验证字段来源、读写往返、损坏文件保护、恢复文件命名、续采比对与价格解析。第三阶段的 JSON 汇总扫描已对真实采集结果验证：65 个商品、选项 `Color`/`Size`，与独立脚本直读原文件的结果一致；同时确认 `links_index.json`、`{域名}.json`、`*_合并.json`、`.recovery-*`、隐藏/临时文件与 `.xlsx` 均被正确排除。

**第三阶段 JSON → 中间表**已用脚本逐项验证：

- 编码往返：含 `& # @ \` 的选项名与值编码后能完整解回。
- 错误中止：含 `$` 的值报错并带上商品名与出错值，且**不留下半成品 xlsx**。
- 段数与价格：3 色 × 2 码产生 6 段；`variant_overrides` 命中的组合取覆盖价，其余取 `default_price`。
- 边界：零选项商品输出 1 行；某一维取值为空时不丢商品；4 维商品截断到 3 维；overrides 引用不存在的值不崩。
- 按勾选裁剪：只勾 Color 时 `styles1` 由 4 段降为 2 段且 `Size` 完全消失；`variant_overrides` 按保留维度命中（只勾 Color 时 `B` 仍取到覆盖价）；勾空或勾不存在的名字退化为单段；未勾选的含 `$` 维度被剔除后不再报错。
- 图片依赖颜色维度：只勾 Color 带图；只勾 Size 不带图；勾 Size+Color（Color 降为第 2 维）不带图；组头名大小写与首尾空格不敏感；名为 Color 但无 `variant_images` 时不写空 `@`。

真实采集结果端到端跑通：`babaroni.co.uk商品.json`（65 条）生成同目录 `babaroni.co.uk商品.xlsx`（66 行含表头）与 `processing_results/` 合并表，字段规范无报错，重复运行结果一致（幂等）。在只有 JSON 的干净目录里：不勾选时每个商品的 `styles1` 为 7~15 段且带图，只勾 Color 时降为 1 段且带图，只勾 Size 时仍为 7~15 段但不带图。

**第四阶段**的选项名匹配已分别验证内嵌编码与传统分列编码：前者从段内 `&名称&值` 取名（勾 Size 正确匹配），后者从 `styles2/styles3` 组头取名，同一位置不同商品用不同选项名时各自正确匹配，匹配不上的组合会记入日志。展开控制已用 12 色 × 5 码 × 3 型的构造表验证：按勾选（Color+Size / 仅 Color / Color+Style / 匹配不上）分别输出 6/2/4/2 行，选项值正确剥离价格后缀，跨位置匹配（勾 Color+Style 跳过中间的 Size）正确留空；`expand_count` 取 1/2/3 分别输出 2/6/12 行（该参数已从界面移除，仅作库级兜底）。已从 GUI 勾选框走通到输出文件：取消勾选 Size 后行数由 12 降为 2；真实数据只勾 Color 时合并表 65 行、转换输出 65 行 Shopify 行，价格匹配与两套 WP CSV 均正常生成。

> 注意：`process_folder` 会把目录里**已存在的** `{域名}商品.xlsx` 一并当作中间表消费。验证减行效果时若目录里留着上一次运行生成的 xlsx，看到的段数会来自那份陈旧文件，需要在只有 JSON 的干净目录里复现。

开发期间曾运行模拟网络和浏览器的三阶段测试，覆盖 Excel 合并导出、续采、停止和保存失败；该历史验证不代表当前版本已完成真实站点全流程采集或店铺导入验证。仓库中**没有**测试套件，早期文档提到的 `tests/test_stage_split.py` 已不存在（该文件从未纳入本仓库）。

首次使用建议先采集一个分类及少量商品，核对标题、品牌、价格、图片和导出结果。
